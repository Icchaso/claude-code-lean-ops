# /brief — 着手前に仕様を固める

対象: $ARGUMENTS

1. 関連する既存コードを必要な範囲だけ確認する。広く読む必要があればサブエージェントに任せ、要約だけ受け取る
2. AskUserQuestion でインタビューする。自明なことは聞かず、仕様の分岐点・エッジケース・UI/UX・範囲外にするもの・トレードオフを聞く
3. ユーザーが想定していなさそうな論点を3つ以内で挙げ、扱いを確認する
4. `SPEC.md` に書き出す: ゴール / 範囲外 / 触るファイルとインターフェース / 完了条件 / 検証方法（可能なら失敗するテストとして書く。最後にE2Eの確認を1つ）
5. 実装は始めない。最後に「`/clear` してから `@SPEC.md を実装して /go`」とだけ案内する
